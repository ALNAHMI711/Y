# ثقافة وطن للمستلزمات العسكرية — منصة وتطبيق

تنفيذ أولي (MVP) لوثيقة التوصيف: خادم Node.js بلا اعتماديات خارجية (HTTP + SQLite المدمجين في Node 22.13+) وتطبيق ويب PWA بالعربية (RTL) يعمل بدون إنترنت.

## التشغيل

```bash
cd server
npm test                       # 13 اختباراً شاملاً
ADMIN_PHONE=967700000001 DEV_OTP=1 npm start   # http://localhost:3000
```

| متغير | الوظيفة |
|---|---|
| `ADMIN_PHONE` | رقم أول مدير (يصبح admin عند أول تسجيل) |
| `DEV_OTP=1` | يُرجع رمز التحقق في الاستجابة للتجربة فقط — **لا يُفعّل في الإنتاج** |
| `INGEST_KEY` | مفتاح تطبيق/جهاز يمرّر رسائل المحافظ إلى `/api/sms/ingest` |
| `WA_TOKEN`, `WA_PHONE_ID`, `WA_TEMPLATE` | إرسال واتساب الحقيقي عبر WhatsApp Cloud API (دون ضبطها يُسجَّل في السجل فقط). خارج نافذة 24 ساعة تشترط Meta قالب رسالة معتمداً. **غير مجرَّب فعلياً** |
| `ANTHROPIC_API_KEY`, `COPILOT_MODEL` | يفعّل تحليل المساعد بنموذج Claude (دونه يعمل تحليل قواعدي مبسّط) |
| `SUPPORT_PHONE` | رقم دعم واتساب لإشعارات التحويلات غير المطابقة |
| `ENC_KEY` / `APP_SECRET` | مفاتيح التشفير والتوقيع؛ تُولَّد تلقائياً في `server/data/` إن لم تُحدَّد |
| `CORS_ORIGINS` | أصول إضافية مسموحة (مفصولة بفاصلة)؛ أصل تطبيق الأندرويد مسموح افتراضياً |
| `DATA_DIR`, `PORT` | مسار البيانات والمنفذ |

اختبارات المتصفح (تتطلب Playwright ولم تُدمج في CI): `python3 e2e/ui_test.py` (إدارة: منتج بصورة، تقارير، خزنة)، `e2e/customer_test.py` (عميل: سلة، عنوان، طلب دفع عند الاستلام، طلب أثناء انقطاع الإنترنت ثم مزامنته)، `e2e/vendor_test.py` (تسجيل تاجر، حالة قيد المراجعة، مراجعة العقد وتفعيله، حساب محفظة، منتج يظهر في المتجر)، `e2e/driver_test.py` (المندوب: مسار، مخطط، تسليم، تسليم دون إنترنت ثم مزامنة).

عند أول تشغيل: سجّل الدخول بـ`ADMIN_PHONE`، ثم من «الإدارة ← الخزنة ← إعداد أولي» عيّن الرمزين (10 أرقام لكل منهما).

## النشر والنسخ الاحتياطي

يعمل فحص تلقائي على GitHub (Actions ← Server tests) لاختبارات الخادم مع كل رفع.

```bash
docker build -t thaqafat-watan .
docker run -d --name tw -p 3000:3000 -v tw-data:/data \
  -e ADMIN_PHONE=967700000001 -e SUPPORT_PHONE=... -e INGEST_KEY=... \
  -e WA_TOKEN=... -e WA_PHONE_ID=... -e ANTHROPIC_API_KEY=... thaqafat-watan
```
أو على VPS بأمر واحد مع HTTPS تلقائي: `cp .env.example .env` ثم عدّله (ضع `DOMAIN` يشير لخادمك) ثم `docker compose up -d --build`. (ملفا Docker و`docker-compose.yml` **لم يُبنيا فعلياً**: لا يوجد docker daemon في بيئة التطوير. جرّبت فقط أمر التشغيل نفسه بالمسارات ذاتها.) ضع خلفه وكيلاً بـ HTTPS (Caddy/nginx/منصة استضافة).

- **نسخ تلقائي**: لقطة يومية في `DATA_DIR/backups` تحتفظ بآخر `BACKUP_KEEP` (افتراضي 14)؛ ويدوياً من «التقارير ← نسخة احتياطية» أو `POST /api/admin/backups`.
- **الاستعادة**: أوقف الخادم، انسخ ملف `app-….db` فوق `DATA_DIR/app.db` (واحذف `app.db-wal` و`app.db-shm`)، ثم شغّل الخادم. جُرّبت قراءة النسخة في الاختبارات.
- ⚠️ **النسخ تحمي القاعدة فقط**: صور البطاقات والعقود مشفّرة بمفتاح في `DATA_DIR/enc.key` (و`app.secret`)، **احفظهما منفصلين خارج الخادم**؛ بدون `enc.key` لا يمكن فك تشفير العقود حتى مع وجود النسخة. وتبقى النسخ على نفس القرص ما لم تنسخها لمكان آخر (التنزيل اليدوي أو مهمة rsync/rclone).

## ما لم يُنفَّذ عمداً

- **نشر المتاجر**: يتطلب حسابات Apple/Google. التطبيق PWA قابل للتثبيت، ويمكن بناء APK تجريبي (انظر أدناه). نسخة iOS وتوقيع الإصدارات للمتاجر غير مُعدّة.

## بناء APK

1. ارفع الخادم على عنوان HTTPS عام.
2. في المستودع: Settings → Secrets and variables → Actions → Variables، أضف `API_BASE_URL` بعنوان خادمك (مثل `https://example.com`).
3. Actions → **Build Android APK** → Run workflow، ثم نزّل `app-debug.apk` من الـ Artifacts.

⚠️ ملف الـ workflow **لم يُجرَّب** (سجل npm محجوب في بيئة التطوير)؛ قد تحتاج تعديلاً بسيطاً عند أول تشغيل. النسخة debug للاختبار فقط وليست للنشر في Google Play.
- **الأتمتة الخفية لتجاوز الحظر (RPA / Headless)**: تخالف شروط المنصات وتعرّض الحسابات للإغلاق؛ استُبدلت بواجهات API الرسمية فقط.
- **تحويل الأموال الفعلي للتجار**: يُسجَّل السحب بحالة `queued`؛ التنفيذ يتم عبر المحفظة/البنك خارج النظام.
- **مبالغ المتاجر (أبل/بلي)** تُدخل يدوياً في الخزنة (لا توجد واجهة آلية).

## ملاحظات أمنية

- **مطابقة الرسائل بالمبلغ فقط معطّلة افتراضياً** (`sms_amount_only_match=0`): لو فُعّلت يستطيع شخص رفع سند وهمي بنفس مبلغ إيداع حقيقي وأخذ رصيده. التطابق الآلي الافتراضي يتطلب **رقم العملية** في الرسالة والسند معاً؛ غير ذلك يذهب للموافقة اليدوية. فعّل الخيار فقط إن قبلت هذا الخطر (وحتى حينها لا يُطابَق إلا عند وجود سند واحد معلّق بذلك المبلغ).
- صور المنتجات تُقبل فقط بصيغة `data:image/(jpeg|png|webp)` وبحجم محدود؛ ومزامنة التطبيق لا تُرسل المنتجات المخفية أو العائدة لتاجر موقوف.
- رؤوس أمان للصفحات (CSP: لا سكربتات إلا من نفس الأصل).

- بطاقات الهوية والعقود مشفّرة في القاعدة (AES-256-GCM)؛ احفظ `ENC_KEY` نسخة احتياطية، فقدانه يعني فقدان البيانات المشفرة.
- النظام ليس «بدون أخطاء» — اختباراتك الميدانية على مسار الدفع والضمان ضرورية قبل التشغيل الفعلي بأموال حقيقية.
- عيّن `DEV_OTP` غير مفعّل، وضع الخادم خلف HTTPS.
